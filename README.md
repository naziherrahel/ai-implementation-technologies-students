# AI Implementation Technologies — student guide

AI Implementation Technologies combines seven lecture sessions, short guided activities in AIT Studio, alternating practical Lab sessions, and one semester team project.

## Course rhythm

- The course meets on Fridays and has **seven lecture sessions** in total.
- Sessions alternate weekly: **one lecture week, followed by one Lab week**.
- **Friday, 4 September 2026:** Lecture 01 and its AIT Studio activity.
- **Friday, 11 September 2026:** Lab 01.
- The lecture/Lab pattern then repeats. Each Lab handout will be added when that Lab is released.

## AIT Studio

Open [AIT Studio](https://nazih-x99.tail283584.ts.net:8443/) in a current browser.

Your account is prepared from the course roster. There is no public registration form.

### Activate your account

1. Receive your personal AIT Studio card from the course instructor.
2. Scan the private QR code once.
3. Choose a private password of at least 12 characters.
4. Return to [AIT Studio](https://nazih-x99.tail283584.ts.net:8443/) and sign in with the username printed on your card and the password you chose.
5. If the card expired or was already used, request a new card from the course instructor.

Your card, activation link, recovery link, and password are private. Do not share, post, or photograph another student's card. Never send your password or private link to anyone.

## Two places, two jobs

| Place | What you do there |
| --- | --- |
| **AIT Studio** | Complete short individual guided activities during lecture weeks. These activities prepare you for the following Lab. Studio activity is practice, not a submission. |
| **Team repository — during Lab weeks** | Create the official team documents, code, evidence, and submissions. Use the same repository throughout the course. |

Studio progress is saved only in local storage for that browser profile on that device; it is not synchronized between devices. Signing out normally keeps the progress, but clearing site data removes it. Another browser, profile, or device will not show the saved progress. Studio activity is practice, not a submission. Once Lab work begins, keep all official project work in the team repository.

## When Lab work begins

- Each team will create one separate repository for the practical work. Do not add Lab work to this course-materials repository.
- Keep the same team repository throughout the course.
- Write setup and run instructions that another team member can follow.
- Use scripts when practical. A notebook is acceptable when it runs from top to bottom without hidden manual steps.
- Do not commit credentials, private links, private data, environments, caches, large datasets, or generated bulk outputs.
- Record limitations and missing work honestly. Never invent model, deployment, monitoring, or test evidence.
- Keep the evidence from each released Lab easy to find.

## If you cannot access Studio

1. Check that you opened the exact `https://` address and included `:8443`.
2. Try a current Chrome, Firefox, or Safari window and, if possible, another network.
